Source-confirmed repairs in V45.3.11
1. Own-profile identity can no longer be overwritten by an unobserved SPA/history transition to another bare creator profile.
   V45.3.10 correctly recorded ownProfilePath, but updateShellForUrl() still trusted ownProfileRoute=true unconditionally and overwrote ownProfilePath with whatever bare /@user route arrived next. The click bridge normally publishes externalProfileOpened() first, but scripted navigation, history restoration or a route transition not originating from that click hook could bypass it. V45.3.11 makes the recorded own path authoritative once learned: a different bare profile switches to external-profile state instead of replacing the user's identity.

2. Returning to the recorded own profile remains self-healing.
   If a different creator is open and WebView history returns to the stored ownProfilePath, ownProfileRoute is restored and the external Back state is cleared. /@user and /@user/ still compare canonically.

3. The fixed 260 ms / 280 ms Back reconciliation race is removed.
   V45.3.10 read web.getUrl() once 260 ms after ordinary mobile/comment Back, and 280 ms after LIVE close. On a slow WebView/history restore this could still be the departure route or transiently blank; the comment-detail branch could then hard-reset to /foryou even though legitimate history navigation was still in progress. V45.3.11 captures the expected history destination before goBack()/goBackOrForward() and uses a bounded reconciliation window instead of treating one timer as authoritative.

4. Slow valid history restoration no longer triggers a Home reset.
   The bounded reconciliation checks at 180 ms and then up to three delayed retries. It only reconciles when the current trusted TikTok route matches the expected destination. A blank/stale route is ignored; after the bounded window WebViewClient callbacks remain authoritative. There is no persistent timer or observer.

5. Comment-detail Back now uses the same history-return state machine as Search/profile/mobile secondary Back.
   The old comment branch had its own fixed-delay URL read and unique fallback behavior. It now captures the actual previous history item, performs Back, and enters the shared bounded reconciliation path. This removes a divergent race-prone path.

6. LIVE close keeps its nearest trusted non-LIVE destination, but reconciliation is now destination-locked.
   V45.3.8's logic for skipping earlier LIVE-room history is preserved. V45.3.11 additionally remembers the exact non-LIVE target selected from WebBackForwardList and waits for that target before applying UA/shell reconciliation.

7. Search history with the same pathname is no longer falsely considered complete.
   /search?q=A and /search?q=B share the same pathname. A path-only comparison could see the still-visible departure query as the expected destination. V45.3.11 includes q (or keyword) in Search history identity while leaving path-addressed TikTok routes unchanged.

8. Pending history reconciliation is generation-fenced and cancelled by explicit navigation/reload/rebuild.
   A new native navigation, UA identity reload, clean Home load, renderer rebuild or Activity destruction invalidates older delayed reconciliation work. This prevents a stale Back callback from repainting shell state after the user has already moved elsewhere.
