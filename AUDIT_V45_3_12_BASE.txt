Source-confirmed mobile-video repair in V45.3.12
1. The old Feed rule forced object-fit:cover on every video regardless of source aspect.
   This is acceptable for the approved portrait/fullscreen path but destructively crops wider media.

2. V45.3.12 keeps the approved portrait geometry and only changes media fit by intrinsic aspect.
   - 9:16-or-taller portrait content keeps object-fit:cover.
   - Media wider than the native 9:16 canvas uses object-fit:contain on a black canvas so the full frame remains visible rather than being aggressively side-cropped.
   - object-position stays centered.

3. Aspect detection does not own the Feed.
   - It only reads videoWidth/videoHeight after normal media lifecycle events.
   - loadedmetadata/play tag the real TikTok <video> element.
   - Two bounded startup passes cover an already-playing first card.
   - No per-swipe scan was added; later cards are handled by normal media events.
   - No play(), pause(), scroll, snap, navigation or DOM replacement is introduced.

4. The approved V45.3.11 CSS is an exact byte-identical prefix of V45.3.12.
   The aspect-fit block is appended at the end, so no previous top/bottom/action/caption/comment/LIVE geometry rule was edited in place.
