Reference observations from the supplied recording
- Launcher: black rounded-square app tile with the cyan/red/white TikTok note centered at a relatively large visual size.
- Startup: pure black screen with the colored TikTok note centered above a white TikTok wordmark; no feed chrome is visible while waiting.
- Startup transitions directly into the feed once content is ready.

V45.3.16 changes
1. Launcher icon proportion lock.
   - Adaptive icon foreground mark scale is increased from 0.62 to 0.68 so the note occupies the icon more like the supplied reference.
   - Legacy ic_launcher.png and ic_launcher_round.png are enlarged by ~9.5% around center while preserving black background and TikTok cyan/red/white mark colors.
   - Application label remains TikTok.

2. Startup waiting page now mirrors the supplied TikTok reference.
   - splash_background.xml is now a black layer-list with the centered TikTok brand asset.
   - New splash_brand.png contains the colored TikTok note above a white TikTok wordmark on transparency.
   - MainActivity adds a full-screen black startup overlay containing the same centered brand, so the brand does not disappear while WebView is still preparing the first page.

3. Startup dismissal is content-bound and bounded.
   - The startup overlay dismisses only after a trusted TikTok main-frame page reaches onPageCommitVisible/onPageFinished, then fades out in 120 ms after a short 180 ms settle.
   - A 12-second bounded escape prevents a network failure from leaving the splash permanently stuck.
   - No recurring timer or observer was added.

4. Android 12+ system splash is aligned.
   - values-v31 Theme.TikShell sets black system splash background, TikTok note animated icon, and zero system splash animation duration.
   - This reduces the default-system-splash flash before the in-app TikTok note + wordmark waiting page.
