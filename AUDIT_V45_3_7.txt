Recovered V45.3.6 repairs
1. Narrow web-app promotion suppression.
   Current public filter-list evidence for TikTok identifies the sessionStorage key webapp_first_open_cta and the styled-component wrappers DivFooterGuide / DivFloatButtonWrapper. The hook sets only that known session value, and CSS hides only those named wrappers inside tk-native-app. There is no text scanner and no generic modal/close-button clicker.

2. LIVE top-entry resolution no longer takes the first arbitrary /live link in the document.
   V45.3.5 queried generic live anchors before/alongside nav-live, so a creator LIVE card in the Feed could be mistaken for TikTok's LIVE navigation destination. V45.3.6 now resolves only [data-e2e="nav-live"] and its own anchor. If that verified nav node cannot yield a link, the native shell falls back directly to https://www.tiktok.com/live.

3. LIVE swipe fallback ignores interactive controls.
   V45.3.5 armed its room-switch fallback for any one-finger touch in LIVE, including touches that started on links, buttons, inputs or text entry. V45.3.6 adds an explicit interactive target guard plus an armed state; touches on a/link/button/input/textarea/select/role=button/contenteditable never participate in the fallback. touchcancel also clears the pending gesture state.

New V45.3.7 source-confirmed repairs
4. Visible secondary Back now uses the same back state machine as Android Back.
   The native secondaryBack icon was wired directly to returnToHomeClean(), while hardware Back already had route-aware logic for comment/search/mobile-secondary/history restoration. This meant tapping the visible Back icon could discard Search/profile/detail history and jump straight to /foryou. The icon now delegates to onBackPressed(), so the visible and hardware Back paths share the same state/history behavior.

5. Cold-start/resume playback recovery rejects hidden or effectively transparent videos.
   The feed gesture layer already filtered display:none, visibility:hidden and near-zero-opacity media, but Java's bounded kickVisibleFeedPlayback() still chose the largest video only by geometry. A preloaded/hidden video with a large rect could therefore receive play() instead of the current visible card. The bounded recovery scan now applies the same style-visibility gate before area ranking.

6. First-card stall inspection uses the same visibility gate for the current article/video and its next-card candidate.
   inspectFirstCardStall() previously treated geometry alone as visible and could classify a hidden/preloaded media node as healthy or as a valid recovery target. A local visibleNode() check now excludes display:none, visibility:hidden and near-zero-opacity article/video nodes. This stays inside the existing bounded cold-start recovery path; no new timer or observer was introduced.
