Source-confirmed repairs in V45.3.8
1. LIVE close returns to the real origin instead of hard-resetting to /foryou.
   V45.3.7 sent every LIVE Back/close through returnToHomeClean(), so entering LIVE from /following, /friends, Search/profile, or another valid TikTok page discarded the actual origin. V45.3.8 inspects WebView's real back/forward list and jumps to the nearest previous trusted non-LIVE TikTok entry.

2. LIVE close skips prior LIVE-room history entries.
   Vertical room switching can create more than one LIVE history entry. A simple one-step web.goBack() can therefore move to the previous room instead of exiting LIVE. The bounded history scan skips LIVE entries and targets the nearest previous non-LIVE TikTok page. If no trusted non-LIVE history entry exists, the existing clean /foryou fallback is retained.

3. Visible LIVE close and Android Back share the same route-aware exit path.
   The native secondary button no longer has a special hard-home LIVE branch. It delegates to onBackPressed(), which now performs the bounded LIVE-history exit above.

4. SPA/main-frame route state no longer leaves mobileLiveMode stale.
   V45.3.7 could leave mobileLiveMode=true after a same-Mobile-UA route moved out of LIVE, because the flag was updated only by a subset of navigation paths. That stale flag could make a later Back act like a LIVE close. shouldOverrideUrlLoading(), onPageStarted(), doUpdateVisitedHistory(), history reconciliation and updateShellForUrl() now synchronize LIVE state from the actual current route.

5. SPA route changes clear stale Search transient state.
   TikTok can change routes through History API without onPageStarted(). V45.3.7's doUpdateVisitedHistory() reconciled UA identity but did not clear searchTransient when the SPA left /search. V45.3.8 clears it whenever the actual navigated route is no longer Search, while preserving the in-place Search-overlay case that is explicitly announced by the bridge.

6. Own-profile state survives photo-detail posts, not only video-detail posts.
   V45.3.7 preserved ownProfileRoute through /video/... but cleared it on /photo/.... Returning from one of the user's own photo posts could therefore be misclassified as an external profile and lose the expected profile bottom state. The preservation gate now uses the existing isPostDetailUrl() definition for both video and photo details.

7. Returning from Mobile secondary pages gets a bounded visible-player wake without Feed auto-advance.
   V45.3.7's first-card recovery is intentionally cold-start-only. After Search/profile/LIVE returns to a Desktop Feed entry, the restored visible video could remain paused while firstCardRecoveryScheduled prevented another cold-start sequence. V45.3.8 marks only Mobile->Desktop Feed identity returns and issues two bounded visible-video play() wakes after restore. It never scrolls or advances the Feed.

8. Return/resume wake now covers /following and /friends as well as /foryou.
   The playback wake helper itself was artificially exact-/foryou limited even though the same Desktop Feed engine is used for Following/Friends. The helper is now Desktop-Feed scoped; the automatic first-card stall/advance logic remains /foryou-only. App onResume performs one bounded wake on whichever Desktop Feed tab is actually active.

9. Renderer rebuild discards transient DOM state and re-arms bounded recovery correctly.
   After a WebView render-process loss, commentOpen/searchTransient/feed recovery state could describe DOM that no longer exists. Rebuild now clears comment presence state, derives Search/LIVE state from the restore URL, re-arms /foryou cold-start recovery, and marks Following/Friends for the non-advancing return wake.

10. Route classification uses TikTok path components instead of whole-URL substring matching.
    The old helpers could misclassify query strings and, importantly, did not treat a root TikTok URL with query parameters as a Feed route even though isForYouUrl() treated the same path as For You. V45.3.8 adds a trusted TikTok page-path parser and path-bound checks for Feed, Discover, Search, Upload, Shop, Inbox and post detail routes. Query parameters no longer control shell identity.
